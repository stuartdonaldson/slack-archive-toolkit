## [Unreleased] — 2026-07-11 to 2026-07-23

_Coverage: 100% — all 15 work-log entries in this range carry v3 facing tags; nothing inferred._

Digest evolution (v2 → v3) reached real-archive verification: evidence fields (reactions, edits,
unfurls), cross-period thread inclusion, a cross-workspace mention index, condensed output, and
now monthly splitting. Backup/export tooling gained selector-based scoping, and the headless auth
keep-alive path had a silent 12-night failure fixed.

### Added

- `export digest --split-by-month` / job field `split_by_month` — one digest document per calendar
  month instead of one merged file. A reply that lands in a later month than its thread's parent
  stays nested with the parent's month (never split into its own entry, never double-counted).
  `--out`/job `out` must contain a literal `{month}` placeholder.
- Digest gains a top-level `mentions` cross-workspace index — answers "where is this PAX
  mentioned" without re-scanning the whole document. Identity matching is deterministic only
  (email hash, or F3-name variants with real-name/username support); conflicting evidence is
  flagged `ambiguous` rather than silently merged.
- Digest evidence preserved end-to-end: reactions, edited flags, message subtype, Slack unfurls,
  `thread_ts` on replies, Pacific-local timestamps (`posted_at_local`), a per-channel `seq` for
  flattened chronological reconstruction, `channel_url`, and message/file anchors.
- A thread whose parent predates the export window but received an in-window reply is now
  included in full, instead of being silently dropped.
- `backup run channels.json <root> --workspace <glob> --channel <glob-list>` — back up a subset of
  tracked channels instead of the whole set.
- `npm run refresh -- <workspace>` (auth-refresh) — refresh/register one named workspace's session
  without stepping through every workspace.
- README gained a "Browse the archive locally" section documenting `slackdump view`.

### Changed

- Digest schema is now `slack-llm-digest-v3`: dropped the redundant `posted_at_utc` field and
  writes compact (no indent) — a real digest measured ~15.7 MB post-condensation vs. ~22.6 MB for
  the equivalent v2 content.
- `backup run`'s cadence-due filtering now happens before the per-workspace sort/interleave, so
  progress counters and interleave spacing reflect only the channels actually processed that run.

### Fixed

- Bot-posted Block Kit backblasts (e.g. F3 Nation crossposts) were losing their `*PAX*:` mention
  list, because mention extraction only read the message's plain text; it now also reads Block
  Kit block text.
- `keepalive.sh` (headless nightly auth refresh) had silently failed (`Permission denied`, lost
  exec bit) for 12 nights; restored and verified against a live auth reset.
- The exporter's month-seal stamp (`.last_backup`) was read but never written, so a quiet
  channel's last-active month was needlessly rewritten on every digest run.

### Documentation

- ADR-0002 (digest v3 condensation) and ADR-0003 (mentions-index deterministic identity) added.
- `docs/DESIGN-export.md` updated for the v3 schema, the mentions index, and monthly digest
  splitting.
- `keepalive.sh` prerequisites are now referenced directly from README, not just
  `docs/OPERATIONS.md`.

### Toward a workspace-agnostic engine

This period's largest architectural change: F3-specific leadership/role inference was extracted
out of the general export engine into a pluggable `handlers/` package (`handlers/f3.py`), selected
via `--leadership-handler` or a job's `leadership_handler` field. The engine itself
(backup/catalog/export/search/registration) has no F3-specific knowledge — a fork targeting a
different community adds a sibling handler module rather than forking the engine. See
`docs/CONTEXT.md` §Purpose "Vision: a workspace-agnostic engine, not an F3 tool" and
`docs/DESIGN-export.md` §Pluggable leadership handlers.

### Added

- `export monthly`, `export digest`, `export users` — bounded per-channel exports, a cross-workspace
  digest, and a full user-roster export, all workspace-agnostic at the engine level
- `search messages` now takes an explicit workspace name/glob argument instead of an implicit
  F3-only scan
- `channel-digest run` — on-demand digest/archive of channels matching a pattern (e.g. recovering
  orphaned content from shuttered channels), generalized (not F3-specific)
- Report jobs (`export digest --jobs 'jobs/*.json'`) — operator-owned, per-recipient digest
  definitions (workspaces, day window, output path, handler), each independently selecting its own
  leadership handler (or none)
- `catalog list` — human-readable channel listing (name, last-updated, message count)
- `handlers/` package and registry (`handlers.get`, `handlers.NAMES`) — the seam that makes the
  above workspace-agnostic; F3's leadership vocabulary is the first and currently only handler
- Tiered backup cadence — active channels backed up nightly, quieter channels on a longer cycle,
  cutting nightly workload

### Changed

- `export digest`/`export users`: `--workspace-glob` renamed to `--workspace`; no longer defaults
  to `f3*` — must be specified explicitly (or supplied per-job via `--jobs`)
- `channel register` now reports *why* a channel was skipped (archived/private/shuttered/already
  registered) instead of silently omitting it; `channel list` flags private channels
- Leadership inference (F3 handler) now also reads the Slack profile `title` field, distinguishing
  AO-scoped roles (Site Q, AOQ, OIC) from regional roles

### Fixed

- Channels that archived zero messages could get permanently stuck (unable to self-heal via
  `resume`); now automatically detected and re-archived from scratch
- Backup logs no longer appear to freeze mid-run (stdout buffering fix)
- Backup throughput improved ~44% by interleaving channels across workspaces instead of draining
  one workspace's rate-limit bucket at a time

### Documentation

- `keepalive.sh` (headless nightly session refresh) prerequisites documented directly in README,
  not just docs/OPERATIONS.md
- `docs/CONTEXT.md`/`docs/DESIGN.md` rewritten to match the actual shipped architecture (previously
  described an abandoned GitHub Actions design)
- Vision statement added making the workspace/community-agnostic engine goal explicit (previously
  implicit in the `handlers/` code, not stated as a goal anywhere)
