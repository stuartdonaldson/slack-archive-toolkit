by `org.f3nation.com` and `map.f3nation.com` (not all of its reads are

these two dates diverge widely, the report's structure/fields may predate a
later API or site change even though the data itself is current.

**How to read a missing position or "(none)":** F3 Nation returned no
assignment for that position at retrieval time. It does not by itself mean
the operational role is vacant -- the assignment may simply never have been
entered in F3 Nation even though someone fills the role in practice. Cross-
check against Slack-visible leadership data (channel topic/purpose, pinned
messages) before reporting a role as vacant; see
[f3-nation-apps.md](f3-nation-apps.md) "Roles and ownership boundaries" for
why these two sources are tracked separately and not auto-synced.

**AO, Location, and Event are separate records** and can have independent
values and status -- an AO can be active with an inactive Location, etc. The
AO description does not appear on org.f3nation.com, map.f3nation.com, or
this report's AO fields (`orgs.description` is never read by the map's
detail query) -- it instead appears on the bot's auto-generated weekly
Calendar graphic. See [f3-nation-apps.md](f3-nation-apps.md) "Field-level
display reference" for the full record-to-field map (Location description →
map "Where", Event description → map "Notes"). Where a **Status** line
appears below for an AO or Event, it reflects that record's own `isActive`
flag from the API -- it is not itself shown on any public F3 Nation site
(only Location's active/inactive state affects what's shown, as noted per
Location below); it's included here for interpretive and troubleshooting
value.

**Where this data can be seen:**
- **org.f3nation.com** — hover/click an org's boundary to see an info panel
  listing *that org's own* filled leadership positions: Nant'an/ITQ/custom
  at the region level, **Site Q at the AO level** (Site Q is not part of a
  region's own roster -- it only shows up when you land on that specific
  AO). Requires being logged in as any PAX (its API, `orgChart.byId`/`.all`,
  is `protectedProcedure` -- no admin/editor role needed, but no anonymous
  reads either). There is no working deep link for an individual AO (see
  module docstring) -- each AO below has its name linked to its default
  workout on map.f3nation.com instead, where that resolves.
- **pax-vault.f3nation.com** — each person named below links to their
  pax-vault stats page (requires sign-in with an F3 email; the link works
  once signed in).
- **map.f3nation.com** — the public workout map: AO contact info, workout
  day/time, and the Location/Event "Notes"/"Where" descriptions. The map
  itself renders without signing in, but its marker click-through detail
  call (`map.location.locationWorkout`) is also `protectedProcedure` in the
  API source -- so an anonymous visitor clicking a marker may hit the same
  login wall (not independently confirmed live; flagging it rather than
  asserting either way). Direct links to each AO's location(s) below, where
  a link exists. **Site Q never appears here** -- see below.

**Where Site Q (and other positions) actually get used:** never on
map.f3nation.com -- it isn't a map-query field at all. Real uses: Slack
pings the Site Q when a backblast posts for their AO, Slack's "Missing
Backblasts" admin view lists each AO's Site Q inline with a "Notify Site Q"
action, and it's shown on org.f3nation.com per above. See
f3-nation-data-model.md (top level of this workspace) § "AO description and
Site Q: where they DO (and don't) show up elsewhere" for the full picture.

**Where to correct something that looks wrong:** AO/Location/Event fields
at **admin.f3nation.com** → the matching section (AOs / Locations / Events).
SLT / Site Q / ITQ / any position assignment: **admin.f3nation.com** →
Positions → Assignments tab, OR Slack `/f3-nation-settings` → SLT config
(same underlying data either way). Full field-by-field routing across all
three public sites: [f3-nation-apps.md](f3-nation-apps.md) "Where
information appears, and where it actually comes from".

**Who can make these corrections:** an F3 Nation app admin, or a user
holding the **editor** or **admin** role on that specific org (region or
AO), granted via admin.f3nation.com or Slack `/f3-nation-settings` -- both
check the same `roles`/`roles_x_users_x_org` tables, so a grant on one
surface is immediately recognized on the other. This report's "who can
correct this" line per region is exactly those role-holders as of the
retrieval time above. (Editing is role-gated; the reads described above are
login-gated but not role-gated -- any signed-in PAX can view them.) See
[f3-nation-apps.md](f3-nation-apps.md) "Roles and ownership boundaries" for
how this role differs from Slack workspace admin and Site Q.
